00

준비물 설치하기

터미널과 클로드가 서로 대화할 수 있는 상태를 먼저 만드는 단계

가장 먼저 컴퓨터에 Node.js가 설치되어 있어야 한다 클로드가 만드는 대부분의 웹앱은 Node.js 위에서 실행되기 때문이다 아직 설치 전이라면 nodejs.org/ko/download에서 LTS 버전을 받아 평소 프로그램 설치하듯 다음(next)만 눌러 설치하면 된다

설치가 끝났다면 터미널(윈도우는 cmd 또는 PowerShell, 맥은 터미널 앱)을 열고 아래 명령어로 잘 설치됐는지 확인해본다

terminal
$ node -v
v20.14.0
# 버전 번호가 안 나오고 에러가 나면 Node.js가 아직 안 깔린 것, 위 링크로 돌아가 설치

Node.js가 준비됐다면 클로드를 터미널에서 실행할 수 있게 해주는 도구를 설치한다 한 번만 하면 된다

terminal
$ npm install -g @anthropic-ai/claude-code
added 1 package in 4s
참고  설치 중 권한 에러가 나면 명령어 맨 앞에 sudo를 붙여 실행 윈도우는 cmd를 관리자 권한으로 열면 대부분 해결된다
01

원하는 기능 정리하기

코드를 짜기 전에 무엇을 만들지 문장으로 먼저 확정하는 단계

클로드는 애매한 요청보다 구체적인 문장을 훨씬 잘 이해한다 아래 세 가지를 종이나 메모장에 먼저 적어보면 다음 단계가 훨씬 수월해진다

  • 무엇을 만들 것인가 예 할 일을 등록하고 완료 체크할 수 있는 웹앱
  • 꼭 필요한 기능 3~5개 예 할 일 추가, 삭제, 완료 표시, 다크모드
  • 나중에 넣어도 되는 기능 예 로그인, 알림 — 처음부터 다 넣으려 하지 않는다
팁  기능을 한 번에 다 요청하지 말 것 처음엔 가장 핵심 기능 하나만으로 뼈대를 만들고 이후 단계에서 하나씩 추가하는 방식이 훨씬 빠르고 정확하다
02

폴더 만들고 클로드에 연결하기

클로드가 실제로 코드를 읽고 쓸 작업 공간을 지정하는 단계

바탕화면이든 문서 폴더든 원하는 위치에 새 폴더를 만들고 그 안으로 들어간다 이 폴더가 앞으로 프로그램의 모든 코드가 담기는 공간이 된다

terminal
$ mkdir my-todo-app
$ cd my-todo-app
$ claude
Welcome to Claude Code
Working directory: ~/my-todo-app

마지막 줄 claude를 입력하는 순간이 핵심이다 이때부터 클로드는 지금 열려 있는 이 폴더를 작업 공간으로 인식하고 여기에 파일을 만들고 읽고 수정한다 처음 실행하면 브라우저 창이 뜨면서 로그인을 요청하는데 클로드 계정으로 로그인하면 연결이 끝난다

03

데이터를 저장하려면 Firebase 준비하기

새로고침해도, 다른 기기에서 접속해도 입력한 데이터가 남아있게 만드는 단계

할 일 목록처럼 사용자가 입력한 데이터를 저장해야 하는 앱이라면 이 단계가 꼭 필요하다 앱 코드만으로는 브라우저를 새로고침하는 순간 입력한 내용이 전부 사라지기 때문이다 데이터를 어딘가에 보관해줄 저장소가 하나 필요한데, 가장 쉽게 시작할 수 있는 게 구글의 Firebase다 회원가입이나 결제 시스템 없이도 데이터베이스를 몇 분 만에 무료로 붙일 수 있다

먼저 브라우저에서 프로젝트를 만들고 연결 정보를 발급받는다

  1. console.firebase.google.com 접속 후 구글 계정으로 로그인
  2. 프로젝트 추가 클릭 → 프로젝트 이름 입력 (예 my-todo-app) → 계속 진행해서 생성
  3. 왼쪽 메뉴에서 Firestore Database 선택 → 데이터베이스 만들기 → 우선 테스트 모드로 시작
  4. 이어서 뜨는 Cloud Firestore 위치 선택 화면에서 반드시 asia-northeast3 (서울)을 선택한다 (목록에 "대한민국" 또는 "Seoul"로 표시됨)
  5. 왼쪽 위 톱니바퀴(프로젝트 설정) → 일반 탭에서 아래로 내려 </> (웹) 아이콘 클릭 → 앱 닉네임 입력 후 등록
  6. 화면에 뜨는 firebaseConfig 코드 전체를 복사해둔다 — 이게 내 프로젝트와 앱을 연결하는 열쇠다
위치 설정 주의  Firestore 위치는 한 번 정하면 나중에 바꿀 수 없다 한국에서 쓰는 서비스라면 속도를 위해 반드시 처음부터 asia-northeast3(서울)로 선택해야 하며, 잘못 골랐다면 되돌리는 방법은 프로젝트를 새로 만드는 것뿐이다
firebaseConfig (복사해둘 것)
const firebaseConfig = {
  apiKey: "AIza...",
  authDomain: "my-todo-app.firebaseapp.com",
  projectId: "my-todo-app",
  ...
};

이제 프로젝트 폴더로 돌아와 터미널에서 Firebase 부품을 설치하고, 방금 복사한 설정을 클로드에게 그대로 붙여넣으며 연결을 요청한다

terminal
$ npm install firebase
added 38 packages in 6s
나

"아래 firebaseConfig로 Firestore를 연결해줘 할 일을 추가·삭제·완료 체크하면 Firestore에 저장되고, 새로고침해도 그대로 불러와지게 해줘
[firebaseConfig 코드 붙여넣기]"

클로드가 src/firebase.js 같은 연결 파일을 만들고 추가·삭제·체크 기능을 Firestore에 읽고 쓰도록 코드를 바꿔준다 이후 04단계에서 npm run dev로 실행해 새로고침해도 데이터가 남아있으면 성공이다

보안 주의  테스트 모드는 누구나 읽고 쓸 수 있는 상태라 연습용으로는 괜찮지만 실제로 다른 사람에게 배포해서 쓰게 하려면 Firestore의 "규칙(Rules)" 탭에서 로그인한 사용자만 접근하도록 반드시 바꿔야 한다 이 부분도 클로드에게 "Firestore 보안 규칙을 안전하게 바꿔줘"라고 요청하면 된다
04

기능을 문장으로 요청하기

클로드가 실제 코드 파일을 폴더 안에 생성하는 단계

연결이 끝났다면 이제 01단계에서 정리한 내용을 그대로 말하면 된다 채팅하듯 편하게 적으면 된다

나

"할 일을 추가하고 삭제하고 완료 체크할 수 있는 웹앱을 만들어줘 리액트로 만들고 완료된 항목은 취소선으로 표시해줘"

이렇게 요청하면 클로드는 아래와 같은 작업을 자동으로 진행한다

  • 필요한 부품(패키지) 목록이 담긴 package.json 생성
  • 화면을 구성하는 컴포넌트 파일들을 src 폴더 안에 생성
  • 진행 상황을 터미널에 실시간으로 표시
terminal
Creating package.json
Creating src/App.jsx
Creating src/components/TodoList.jsx
Done — 3 files created
05

터미널에서 실행해서 눈으로 확인하기

머릿속 아이디어가 실제 화면으로 바뀌는 순간

클로드가 코드를 다 만들었다면 이번엔 그 코드를 직접 실행해서 브라우저로 확인할 차례다 클로드에게 실행까지 부탁해도 되고 아래처럼 직접 입력해도 된다

terminal
$ npm install
added 214 packages in 12s
$ npm run dev
Local: http://localhost:5173

터미널에 뜬 localhost 주소를 복사해서 브라우저 주소창에 붙여넣으면 방금 만든 화면이 그대로 보인다 이 순간부터가 진짜 "구동하는 프로그램"이다

06

수정하며 반복하기

이 반복이 사실상 개발의 전부다

화면을 보다가 마음에 안 드는 부분이 있으면 바로 클로드에게 말한다

나

"완료 체크된 항목 글자색을 회색으로 바꾸고 버튼에 둥근 모서리를 줘"

클로드가 코드를 수정해서 저장하면 브라우저가 자동으로 새로고침되며 바뀐 화면이 바로 보인다 이 요청 → 확인 → 다음 요청의 흐름을 원하는 만큼 반복하면 된다

문장으로 요청
→
클로드가 코드 수정
→
브라우저 자동 새로고침
→
눈으로 확인
↺ 마음에 들 때까지 반복
화면이 안 바뀔 때  터미널에서 Ctrl + C로 서버를 끄고 npm run dev로 다시 켜본다 그래도 이상하면 터미널에 뜬 에러 문구를 통째로 복사해 클로드에게 붙여넣고 고쳐달라고 하면 된다
07

배포하기

내 컴퓨터 안에서만 보이던 화면을 누구나 접속 가능한 주소로 내보내는 단계

지금까지는 localhost 주소라서 내 컴퓨터에서만 보인다 다른 사람도 접속할 수 있게 하려면 배포 과정이 필요하다 가장 간단한 방법은 Vercel이라는 배포 서비스를 쓰는 것이다

terminal
$ npm install -g vercel
$ vercel
? Set up and deploy "my-todo-app"? [Y/n] y
? Link to existing project? [y/N] n
✓ Production: https://my-todo-app.vercel.app

질문 몇 개에 엔터만 눌러도 대부분 기본값으로 진행된다 완료되면 실제 웹 주소가 발급되고 이 주소를 아무에게나 보내면 그 사람 브라우저에서도 똑같은 화면이 열린다 Netlify나 GitHub Pages도 같은 방식으로 동작하는 대안이다

08

배포 후에도 계속 발전시키기

한 번 배포했다고 끝이 아니라 여기서부터가 진짜 시작

배포된 뒤에도 같은 폴더 안에서 claude를 다시 실행해 기능을 계속 추가할 수 있다 흐름은 05~07단계와 완전히 같다

  1. 같은 폴더에서 claude 실행 후 새 기능 요청
  2. npm run dev로 로컬에서 먼저 확인
  3. 마음에 들면 vercel --prod로 정식 재배포
terminal
$ vercel --prod
✓ Production: https://my-todo-app.vercel.app

기능을 정리하고 → 폴더에서 요청하고 → 확인하고 → 배포하는 이 사이클 자체가 하나의 도구가 되는 순간 아이디어가 떠오를 때마다 같은 순서를 반복하기만 하면 된다

명령어 치트시트

단계마다 나온 명령어를 한 곳에 모았다

명령어하는 일
node -vNode.js가 설치되어 있는지 확인
mkdir 폴더명새 프로젝트 폴더 생성
cd 폴더명해당 폴더 안으로 이동
claude현재 폴더를 클로드에 연결해 대화 시작
npm install코드 실행에 필요한 부품 전체 설치
npm run dev로컬 미리보기 서버 실행
npm install firebase데이터 저장(Firestore) 연결에 필요한 부품 설치
npm install -g vercel배포 도구 설치 (처음 한 번)
vercel임시 배포 주소 발급
vercel --prod정식 주소로 재배포
Ctrl + C실행 중인 서버 멈추기
exit클로드 세션 종료

자주 묻는 질문

막히기 쉬운 지점들을 미리 모아뒀다

가능하다 코드를 직접 짤 필요는 없고 원하는 결과를 문장으로 구체적으로 설명하는 능력이 더 중요하다 다만 에러 메시지가 뜨면 당황하지 말고 그대로 복사해서 클로드에게 전달하는 습관만 있으면 충분하다

다른 프로그램이 같은 포트(예 3000번)를 이미 쓰고 있다는 뜻이다 기존 서버를 Ctrl + C로 끄거나 클로드에게 "포트 번호를 바꿔서 다시 실행해줘"라고 요청하면 된다

대부분 코드 어딘가에 에러가 있다는 신호다 터미널이나 브라우저 개발자 도구에 뜬 에러 메시지를 통째로 복사해 클로드에게 붙여넣고 원인을 찾아 고쳐달라고 요청한다

터미널이 지금 프로젝트 폴더 안에 있는지부터 확인한다 pwd(맥) 또는 cd(윈도우)로 현재 위치를 확인하고 아니라면 cd 폴더명으로 다시 이동한 뒤 claude를 실행한다

이미지 경로나 환경변수 설정이 다른 경우가 많다 배포 서비스가 보여주는 로그 화면을 그대로 캡처하거나 복사해서 클로드에게 보여주고 원인을 물어보면 대부분 바로 찾아낸다

개인 프로젝트나 소규모 사용 수준에서는 무료 요금제(Spark 플랜)로 충분하다 저장하는 데이터 양이나 읽기·쓰기 횟수가 아주 많아지면 유료 플랜으로 넘어가야 하는데, 그 시점은 콘솔의 사용량 화면에서 미리 확인할 수 있다

처음이라면 이 가이드에서 쓴 Firestore를 추천한다 데이터를 표처럼 정리하기 편하고 구글에서도 신규 프로젝트에 더 권장하는 쪽이다 클로드에게 그냥 "Firestore로 연결해줘"라고 하면 알아서 맞춰준다

요청을 잘 쓰는 법

한 번에 하나씩

기능 다섯 개를 한꺼번에 요청하기보다 하나씩 요청하고 확인하는 편이 결과가 훨씬 정확하다

결과 중심으로
